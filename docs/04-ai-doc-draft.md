# AI 활용 기술 문서 (제출용 PDF 초안) — 《도플 DOPPEL》

> 상태: W2 골격. 방어 논리(§1·§4)는 완성, 구현 상세·프롬프트 기록은 W3에서 채움.
> 이 문서는 2층 구조다: **①게임 속 AI**(런타임에 플레이어를 배우는 분신)와 **②제작 과정 AI**(Claude를 어떻게 부렸는가). 대부분의 제출작은 ②만 있을 것이다. 이 게임은 ①이 본체다.

## 1. 왜 LLM을 안 썼는가 (먼저 답한다)

이 게임의 런타임 AI는 LLM이 아니라 **행동 통계 모델**이다. 의도된 선택이고, 이유는 세 가지다.

1. **한돌도 LLM이 아니다.** 게임 AI의 본질은 "그럴듯한 말"이 아니라 "플레이어의 데이터를 학습해 플레이어의 상대가 되는 것"이다. NHN이 한게임 기보로 한돌을 만든 것과 같은 계보의 문제를, 1인 스케일로 풀었다.
2. **심사자가 5초 안에 실행할 수 있어야 한다.** API 키·과금·지연시간·프롬프트 실패가 전부 0이다. 링크를 열면 바로 돌고, 비행기 모드에서도 돈다.
3. **검증 가능해야 한다.** 분신의 모든 판단은 "당신의 선택 N회 관찰"로 소급된다. 분신이 왜 그렇게 뒀는지 노트로 근거를 보여줄 수 있고, 지어내지 않는다. LLM이었다면 이 정직함을 보장 못 한다.

LLM(Claude)은 ②제작 과정에서 전면적으로 썼다. 도구를 안 쓴 게 아니라, **각 층에 맞는 AI를 골랐다.**

## 2. 게임 속 AI — 분신 엔진

### 2-1. 상태 버킷 (18)

상황 = 더미 점수 3구간(0~3 / 4~7 / 8+) × 점수차 3구간(±3 기준) × 폭탄 위험 2구간(남은 폭탄/남은 카드 0.25 기준). 전부 공개 정보만 사용 — 분신은 내가 보는 것만 보고 배운다.

- 선택이 GO/STOP 2지선다라 버킷당 표본 3개면 예측이 시작된다 (5지선다였던 초기 설계를 폐기한 이유)
- 진짜 선택이 있었던 순간만 학습 (첫 장 강제 뽑기는 기록하지 않음)

### 2-1b. 백오프 추론 (핵심 기법)

한 라운드에서 기록되는 진짜 선택은 2~4개뿐이다. 정확한 18버킷만 기다리면 분신은 몇 세션이 지나도 말을 못 한다. 그래서 n-gram 백오프와 같은 방식으로 좁은 상황 → 넓은 상황 순으로 근거를 찾는다:

```
L0 더미×점수차×위험  →  L1 더미×점수차  →  L2 더미만  →  L3 전체 성향
```

핵심은 **어느 층에서 말하는지를 항상 밝히는 것**이다. L0에서 나온 예측은 "여기선 무조건 가십니다"라고 단정하고, L3에서 나온 예측은 "(평소 성향 기준) 이건 감인데…"라고 스스로 낮춘다. 확신을 표본 수에 비례시키는 이 처리가 조기 발화와 정직성을 동시에 만족시킨다.

측정 결과: 백지 상태에서 **두 번째 선택 만에 첫 예측 발화**(자동 플레이 7.2초).

### 2-1c. 스킬 타이밍 학습 (두 번째 학습축)

GO/STOP 외에 스킬 3종(방패·투시·배증, 세션당 각 1회)이 있고, **분신은 "언제 그 스킬을 꺼냈는지"를 따로 학습한다.**

- 사용한 순간의 상황만 기록한다 — 안 쓴 순간을 매 턴 기록하면 노이즈가 압도한다
- 상황을 3중으로 집계: 정확한 버킷 / 점수차 성향 / 더미 성향 → 가중 합으로 "지금 이 상황이 그 사람이 쓰던 상황인가"를 0~1로 산출
- 거울전에서 분신은 그 값이 높을 때 같은 스킬을 꺼낸다: *"✕2 배증. 사장님이 쓰시던 타이밍이잖아요."*

검증: "지고 있을 때 배증" 5회 주입 → 같은 상황에서 169/200 사용, 이기고 있는 상황에서는 0/200. 성향이 상황에 조건부로 재현된다.

이 설계의 요점은 **재미 요소가 AI 컨셉을 강화한다**는 것이다. 스킬은 게임을 재밌게 만들면서 동시에 분신이 배울 성격 데이터를 늘린다.

### 2-2. 정직 원칙

- 표본 3 미만 버킷 = "아직 못 배운 상황"으로 표시. 채워넣지 않는다
- 거울전에서 분신이 미학습 상황을 만나면 기본기(기대값 규칙)로 두고, **그 사실을 말한다** ("이 상황은 아직 안 배웠어요")
- 일치율 = 최근 30선택에서 예측 적중 비율. 표본 5 미만이면 "측정 전"

### 2-3. 분신 플레이

버킷 분포에서 확률 샘플링 + 내 평균 결정 시간을 흉내 낸 템포 연출. (W3에서: 코드 발췌·수식 정리)

### 2-4. 스파링 AI 3종

불도저(더미 크기만 봄) / 회계사(기대값 계산) / 여우(점수차 기반 분기). 규칙 기반 + 노이즈 — 성향이 읽혀야 분신의 노트가 서사가 된다.

## 3. 제작 과정 AI — Claude를 어떻게 부렸는가

(W3에서 채움: 실제 프롬프트 발췌 + 세션 로그 요지)

- 역할 분담: 사람 = 문제 정의·채점 기준·최종 취향 / AI = 리서치·구현·검증 실행
- **채점기를 먼저 만들었다**: 심사 루브릭(judge-rubric.md)을 컨셉 확정 전에 작성, 8개 후보를 채점해 97점 안을 선택. 만들고 나서 평가받는 게 아니라, 평가 기준에서 역산해 만들었다
- 코어 교체 의사결정 기록: 직접 플레이 → 도파민 부족 판정 → 쇼다운을 《한 장 더》로 교체 (커밋 8a77823). 과정 전체가 커밋 로그에 남아 있다
### 3-1. 에셋 출처 — 외부 에셋 0건

| 항목 | 방식 | 출처·라이선스 |
|---|---|---|
| 분신 얼굴 | 인라인 SVG(원·패스·그라디언트)를 코드로 생성. 선명도에 따라 블러·눈·입이 실시간 변형 | 자체 제작 (Claude 협업) |
| 카드·보석·UI | 순수 CSS (그라디언트·애니메이션) | 자체 제작 |
| 효과음 8종 | **WebAudio 실시간 합성** — 오실레이터·노이즈 버퍼로 즉석 생성. 오디오 파일 0개 | 자체 제작 (`js/sfx.js`) |
| 폰트 | OS 기본 산세리프 (Apple SD Gothic Neo / 맑은 고딕) | 시스템 폰트 |

이미지·오디오 파일을 하나도 쓰지 않았다. 저작권 리스크가 0이고, 로딩이 0이며, 저장소가 가볍다 — 심사자가 링크를 누르면 즉시 실행되는 조건과 직결된다.

## 4. 예상 반론과 답

| 반론 | 답 |
|---|---|
| LLM도 안 쓰고 AI 게임인가 | §1. 게임 속 AI의 본질은 학습·판단이지 언어가 아니다. 한돌 계보 |
| 통계 모델이 너무 단순하다 | 단순한 게 목적이다. 표본 수십 회로 "나 같다"가 나와야 하고, 판단 근거를 사람에게 보여줄 수 있어야 한다. 복잡도는 요구사항이 아니라 리스크였다 |
| 웹보드 게임 아닌가 | 카드가 아니라 선택을 배우는 게임 (게임 소개 §4). 사행성 0, 확률 전부 공개 |
| 모방이 정말 되나 | 일치율 게이지가 라이브 증거. 블라인드 테스트 결과 (W3에서: N명 중 M명 "나 같다" 응답 기록) |

## 5. 한계 (숨기지 않는 것)

- 표본이 적은 초반 분신은 서툴다 — 그걸 성장 서사로 설계했지만, 짧게 플레이하면 학습 전 상태만 보게 된다 → 심사자 모드(?demo)로 보완
- 버킷 모델은 상황 간 일반화를 못 한다 (배운 상황만 안다) — 의도된 트레이드오프지만, 더 큰 상태공간의 게임엔 그대로 이식 불가
