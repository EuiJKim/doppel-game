# AI 활용 기술 문서 (제출용 PDF 초안) — 「회귀한 마왕은 나의 타워를 기억한다」

> 상태: 8/7 TD 기준 전면 재작성. PDF 변환 시 코드 발췌·스크린샷 삽입.
> 이 문서는 2층 구조다: **①게임 속 AI**(런타임에 플레이어를 읽고 응수하는 마왕 디렉터)와 **②제작 과정 AI**(Claude를 어떻게 부렸는가). 대부분의 제출작은 ②만 있을 것이다. 이 게임은 ①이 본체다.

## 1. 왜 LLM을 안 썼는가 (먼저 답한다)

이 게임의 런타임 AI는 LLM이 아니라 **로컬 디렉터**(결정론적 분석 + 학습 통계)다. 의도된 선택이고, 이유는 세 가지다.

1. **게임 AI의 본질은 언어가 아니라 판단이다.** NHN이 한게임 기보로 '한돌'을 만들었듯, 이 마왕은 플레이어의 빌드 데이터를 읽어 플레이어의 상대가 된다. 같은 계보의 문제를 1인 스케일로 풀었다.
2. **심사자가 5초 안에 실행할 수 있어야 한다.** API 키·과금·지연시간·프롬프트 실패가 전부 0이다. 링크를 열면 바로 돌고, 비행기 모드에서도 돈다.
3. **검증 가능해야 한다.** 마왕의 모든 선언은 실제 편성으로 소급된다. "선언한 유닛이 정말 오는가"를 자동 계측으로 측정했고(§4), 거짓 선언 0건을 보증한다. LLM이었다면 이 무결성을 보장 못 한다.

LLM(Claude)은 ②제작 과정에서 전면적으로 썼다. 도구를 안 쓴 게 아니라, **각 층에 맞는 AI를 골랐다.** LLM을 게임에 넣는 확장 방향은 §7.

## 2. 게임 속 AI — 마왕 디렉터

매 웨이브 직전에 도는 파이프라인. AI 개입 지점 6개 전부가 플레이어 눈에 보인다.

| # | 지점 | 무엇을 하나 | 어떻게 보이나 |
|---|---|---|---|
| 1 | **읽기** | 타워 투자를 비용 가중으로 분석 — 설치비 + 강화비 합산. 화살탑에 몰빵 강화하면 그만큼 위협으로 읽는다 | 붉은 스캔 빔이 타워를 훑고, 최다 투자 타워에 락온 마커 + "읽힘" |
| 2 | **편성** | 상성표에서 카운터 유닛 선정, 주력 60% + 혼합 40%. 예산 하드캡 안에서만 (§3) | 선언한 유닛이 웨이브의 주력으로 온다 |
| 3 | **전술** | 스플래시 투자 비중 ≥ 34% → 산개 스폰(900ms 간격) / 단일딜 비중 ≥ 55% → 밀집 러시(150ms) | *"흩어져서 간다."* / *"한꺼번에 간다."* — 실제 간격이 그렇게 나온다 |
| 4 | **선언→실행** | 편성 확정 후 선언, 1.7초 뒤 그대로 실행. 비용 게이트를 선언 이전에 적용해 거짓말을 구조적으로 차단 | 선언 배너 + 화면 흔들림. §4에서 무결성 계측 |
| 5 | **반복 방지** | 동일 주력 연속 금지 → 차선 카운터 → 혼합 웨이브, 3로테이션. 예외: 지난 웨이브에 뚫린 유닛은 배가 | *"같은 수는 두 번 안 쓴다."* / *"철갑충이 통했지. 그래서 더 간다."* |
| 6 | **회귀 기억** | 런 종료마다 localStorage에 기록: 주력 타워 성향, 초반 빌드(오프너), 뚫은 유닛, 전적 | 개전 인사 *"회귀 N번째다. 넌 M판 중 K판을 화살탑으로 시작했지"* + 회귀록 화면 |

### 2-1. 상성표 (마왕의 뇌)

| 플레이어 투자 | 주력 카운터 | 이유 |
|---|---|---|
| 화살탑 (연사) | 철갑충 → 철갑 쥐떼 | 방어 = 타격당 고정 감산. 잔딜을 흡수한다 |
| 대포탑 (스플래시) | 질풍 늑대 → 오우거 | 산개 고속 단일 / 뭉칠 이유가 없는 한 덩어리 |
| 마법탑 (감속) | 망령 → 오우거 | 감속 면역 / 맷집 (단, 마법 피해는 방어 무시 — 철갑의 천적) |
| 저격탑 (한방) | 철갑 쥐떼 → 쥐떼 | 한 발에 한 마리 = 오버킬 낭비. 방어 높고 체력 낮은 물량 |

철갑 쥐떼는 실플레이 인사이트("한방 타워 앞의 방어 높고 체력 낮은 몹이 가장 당황스럽다")를 유닛으로 번역한 것이다 — 한방과 연사를 동시에 카운터한다.

### 2-2. 회귀 학습 (런 간 기억)

- 기록: 총 전적(runs/wins/losses), 주력 타워 이력 8판, 오프너 이력 8판(웨이브 3 시점 스냅샷), 가장 잘 뚫은 유닛
- 예산 계수 = 1 + 0.08 × (마왕이 격퇴당한 횟수). **이기는 유저에게만 걸리는 군비경쟁** — 고전하는 유저를 조이지 않는다
- 회귀록 화면: 기억을 숫자와 함께 낭독. 2판 이상 반복된 성향만 "버릇"으로 언급 — 표본 1개로 단정하지 않는다 (정직 원칙)

### 2-3. 웨이브 10 — 마왕 강림

마지막 웨이브에는 마왕 본체가 직접 온다. 세 가지가 설계 포인트다.

- **본체도 예산에서 차감된다** (비용 120) — 클라이맥스조차 §3의 하드캡 안이다. 치트로 만든 보스전이 아니다
- 호위는 **이번 런에서 내 방어를 가장 잘 뚫은 유닛**이 맡는다: *"철갑충이 앞장선다 — 네게 통했던 놈이다."* 한 판 안의 학습이 마지막 웨이브로 수렴한다
- 본체 침투 시 목숨 −5. 격퇴하면 승리 — 그리고 마왕은 그 패배를 기억한 채 회귀한다

## 3. 공정한 권한 — 마왕도 치트 불가

AI 디렉터가 신뢰받으려면 권한이 명시적이어야 한다.

- **예산 하드캡**: B(n) = 46 + 28n (웨이브 6까지), 이후 214 + 22(n−6). 회귀 계수가 붙어도 이 함수 × 계수를 넘을 수 없다. 웨이브 10의 마왕 본체(120)도 여기서 차감
- **읽는 정보 = 플레이어도 보는 정보**: 타워 종류·위치·강화 투자뿐. 골드 잔액, 목숨, 판매 계획은 읽지 않는다
- **유닛 비용 상한**: 8 + 4n — 초반부터 오우거를 못 낸다. 웨이브 1은 전술 미적용 + 예산 75% (온보딩 자비)
- 마왕의 강함은 치트가 아니라 **읽기의 정확함**에서 나온다

## 4. 검증 — 선언→실행 무결성 계측

"AI가 정말 개입하는가"를 주장이 아니라 수치로 답한다. 자동 프로브(디렉터 출력과 실제 스폰 큐 대조)로 측정했다.

| 지표 | 결과 |
|---|---|
| 선언 유닛의 실제 웨이브 점유율 | 평균 47%, 후반 웨이브 61% — "말한 놈이 주력으로 온다" |
| 전술 선언 정합 (산개/밀집 선언 vs 실제 스폰 간격) | 9/9 (100%) |
| 거짓 선언 | **0건** |
| 대사 다양성 | 런당 도발 8종 (대사 풀 비반복 선택) |

계측이 결함도 잡았다: 초기 버전은 비용 게이트가 선언 *후에* 적용돼 웨이브 1에서 "강철을 뚫을 셈인가" 선언 후 철갑충이 0마리 나오는 거짓말이 있었다. 게이트를 선언 앞으로 옮기고, 다운그레이드 시 정찰 톤 대사(*"첫 수부터 패를 깔 수는 없지"*)로 교체해 0건을 만들었다. **선언→실행 무결성은 이 게임 신뢰의 핵심이라, 기능이 아니라 테스트로 보증한다.**

밸런스도 시뮬레이션으로 검증: 자동 플레이어 풀런(마왕 강림 포함) 기준 균형·도배 빌드 모두 목숨 5~6으로 완주 — 도배를 벌하되 죽이지는 않는 압박. 상성에 맞춰 대응하는 실제 플레이는 그 이상이 나온다.

## 5. 제작 과정 AI — Claude를 어떻게 부렸는가

역할 분담: **사람 = 문제 정의·채점 기준·최종 취향 판정 / AI = 리서치·구현·검증 실행.**

- **채점기를 먼저 만들었다**: 심사 루브릭(judge-rubric.md)을 컨셉 확정 전에 작성하고, 매 라운드 같은 자로 자가 채점했다. 만들고 나서 평가받는 게 아니라 평가 기준에서 역산해 만들었다
- **3번 피벗했고, 전부 기록했다**: 카드(도파민 부족 판정) → 결투(AI 비가시성 판정) → 아레나(패턴 다양성 부족) → TD. 각 판정은 제작자가 직접 플레이해서 내렸고, 버린 게임 셋도 레포에 플레이 가능한 상태로 남겼다
- **자동 유저테스트**: 5개 전략(화살 도배·저격 도배·균형 등)을 시뮬 플레이어로 돌려 밸런스 벽과 "전 전략 승리 = 식는 상태"를 수치로 발견·수술했다
- **UX 계측 프로브**: §4의 무결성 지표는 사람이 눈으로 센 게 아니라 Claude가 작성한 자동 프로브의 출력이다
- 실플레이 피드백("웨이브 7부터 벽") → 원인 3개 수술(회귀 계수 방향 버그, 강화 부재, 예산 곡선) — 과정 전체가 한글 커밋 로그에 있다

## 6. 에셋 출처 — 외부 에셋 0건

| 항목 | 방식 | 출처·라이선스 |
|---|---|---|
| 맵·타워·유닛·이펙트 | 캔버스 2D 코드 렌더링 (도형·그라디언트) | 자체 제작 (Claude 협업) |
| 효과음 전체 (발사 4종·락온·심장박동·결정타 등) | **WebAudio 실시간 합성** — 오실레이터·노이즈 버퍼. 오디오 파일 0개 | 자체 제작 |
| 폰트 | OS 기본 산세리프 | 시스템 폰트 |
| 아이콘 | OS 이모지 | 시스템 제공 |

이미지·오디오 파일을 하나도 쓰지 않았다. 저작권 리스크 0, 로딩 0 — 심사자가 링크를 누르면 즉시 실행되는 조건과 직결된다.

## 7. 확장 방향 — LLM은 어디에 붙나

판단은 로컬에 남기고, **언어만 LLM에 맡기는** 구조가 준비돼 있다. 디렉터의 출력(읽기 결과·편성·전술·회귀 기억)은 이미 구조화된 데이터라, 이를 프롬프트로 넘겨 마왕 대사를 생성형으로 바꾸면 대사 풀의 한계를 넘는다. 판단·예산·상성은 그대로 검증 가능하게 유지되므로 §4의 무결성 보증이 깨지지 않는다. 본선에서는 여기에 스테이지 생성(경로·건설 지점 배치)을 얹는 로드맵을 제시한다.

## 8. 한계 (숨기지 않는 것)

- 상성표는 손으로 설계했다 — 마왕이 배우는 건 "이 플레이어의 성향"이지 "새로운 상성"이 아니다
- 회귀 기억은 기기(localStorage) 단위다 — 브라우저를 바꾸면 마왕은 처음 보는 척한다
- 대사는 상황별 풀에서 뽑는다 — 회차가 아주 길어지면 반복이 체감될 수 있다 (§7의 LLM 레이어가 답)
