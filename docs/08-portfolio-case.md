# 포트폴리오 케이스 — 회귀한 마왕은 나의 타워를 기억한다

> 기획자가 AI를 디렉팅해서, 게임 개발 경험 0에서 4주 만에 플레이 가능한 AI 게임을 만든 기록.
> 플레이: https://euijkim.github.io/doppel-game/game/td/ (설치·계정 없음, 링크 클릭이 전부)

## 한 줄

**"AI를 활용하는 사람"이 아니라 "AI를 디렉팅하는 사람"임을 증명하려고 만든 프로젝트.** 코드는 AI(Claude)가 짰다. 문제 정의, 채점 기준, 버릴지 말지의 판정 — 사람 몫은 전부 내가 했다.

## 무엇을 만들었나

타워 디펜스인데, 웨이브가 미리 짜둔 테이블이 아니라 **AI 디렉터**다. 마왕이 매 웨이브 내 타워 배치를 읽고 → 카운터 부대를 편성하고 → **먼저 선언하고 → 선언한 그대로 공격한다.** 죽어도 끝이 아니다 — 내 빌드 버릇을 기억한 채 회귀해서 다음 판에 더 강하게 돌아온다.

- 순수 HTML/CSS/JS, 프레임워크 0, 외부 API 0, 에셋 파일 0 (사운드까지 WebAudio 코드 합성)
- 플레이 영상 51초, 설계·검증 문서 전부 공개 (레포 커밋 로그 = 의사결정 기록)

## 어떻게 일했나 — 기획자의 AI 디렉팅 5원칙

### 1. 채점기를 먼저 만들었다
만들기 전에 "이걸 심사할 사람이 뭘 보고 판단하는가"부터 역설계했다. 심사자 페르소나 2종(기계적 검증 렌즈 / 바쁜 실무자 렌즈)으로 루브릭을 만들고, 매 라운드 같은 자로 쟀다. 점수 추이: 1R 논리 45/취향 56 → 최종 논리 82/취향 78. **만들고 평가받는 게 아니라, 평가 기준에서 역산해 만들었다.**

### 2. 재미는 측정 대신 판정했다 — 그리고 3번 버렸다
카드 게임(도파민 부족) → 반응 대전(AI 개입이 안 보임) → 오토배틀러(패턴 부족) → TD. 매번 내가 직접 플레이하고 판정해서 버렸고, 버린 이유를 기록했다. 버린 게임 3개도 레포에 플레이 가능한 상태로 남겨뒀다 — **과정을 숨기지 않는 게 내 포트폴리오의 원칙이다.**

### 3. 도메인 경험을 시스템으로 번역했다
내가 TD 유저로서 아는 것 — "한방 타워를 도배했을 때 방어력 높고 체력 낮은 물량이 나오면 심장이 내려앉는다" — 를 AI에게 전달해 '철갑 쥐떼' 유닛과 상성표로 번역시켰다. 프롬프트가 곧 기획서였다. (실제 프롬프트 원문은 AI 기술 문서에 공개)

### 4. AI의 정직함을 계측으로 보증했다
AI 게임의 약점은 "정말 AI가 한 건지" 안 보인다는 것. 그래서 마왕이 수를 먼저 말하고 그대로 두게 설계하고, **선언→실행 일치를 자동 계측**했다: 선언 유닛의 실제 웨이브 점유율 평균 47%(후반 61%), 전술 선언 정합 9/9, 거짓 선언 0건. 계측이 실제 결함도 잡았다 — 초기 버전은 웨이브 1에서 마왕이 선언한 유닛을 예산 부족으로 못 보내는 '거짓말'이 있었고, 게이트 순서를 바꿔 0건으로 만들었다.

### 5. 밸런스는 시뮬레이션으로 수술했다
자동 플레이어 5종(화살 도배·저격 도배·균형 등)으로 풀런을 돌려 "웨이브 7 벽", "전 전략 무손실 승리(긴장 소멸)" 같은 문제를 수치로 발견하고 고쳤다. 실플레이 피드백("7부터 너무 어렵다")의 원인을 파니 밸런스 숫자가 아니라 **회귀 계수의 방향 버그**(지는 유저에게 군비경쟁이 걸리던 것)였다 — 증상이 아니라 구조를 고쳤다.

## 역할 분담 (정직하게)

| | 사람 (나) | AI (Claude) |
|---|---|---|
| 한 일 | 문제 정의, 심사 기준 설계, 재미 판정, 피벗 결정, 도메인 인사이트, 최종 취향 | 코드 전체, 리서치, 시뮬레이션·계측 실행, 문서 초안 |
| 못 하는 일 | 4주에 혼자 이걸 구현하는 것 | 뭐가 재밌는지 아는 것, 뭘 버릴지 정하는 것 |

## 결과와 배운 것

- 게임 개발 경험 0 → 4주, 1인 + AI로 완주 가능한 게임·영상·기술문서 완성
- NHN NAN 2026 해커톤 사전과제 규격으로 제작. **제출은 못 했다 — 마감 전 "더 다듬고 싶다"에 붙잡혔다.** 자가채점 82/78이 말해주듯 부족한 건 게임이 아니라 제출 버튼이었고, 이 경험으로 얻은 원칙: **마감이 있는 판에서는 완벽한 미제출보다 부족한 제출이 이긴다.** 다음 판에서는 이 기록이 확신을 대신한다
